## 更新する担当の手順
1. GitHub mainを取得して最新SHAを保持。既存の作業を上書きしない。
2. data/campaigns.json、data/site.json、docs/RESEARCH.jsonと本書を読む。
3. 公式公開情報だけを閲覧。各情報源の規約・robots・アクセス制限をその回に確認し、禁止された機械取得や認証回避はしない。現行情報源の無人HTTP取得は許可未確認でOFF。検索抜粋だけではverifiedに昇格しない。
4. 必須条件と期限を照合。未取得・ログイン内・不明はnull/unknown/pendingを維持する。最終確認日時は条件を確認した時だけ更新。
5. 新規・変更は自作要約、sourceUrls、確認日時、historyへ変更理由を記録。公式URL重複は別案件として作らず既存を更新。購入・会員登録・SNSはtrue/false/nullの3値。
6. 取得失敗はlastVerifiedAtを保持してpendingへ。情報源本文変更はhash付き観測をrefreshに渡してpendingへ（ハッシュ一致だけでは確認日時を更新しない）。再確認できた時だけverifiedへ戻す。
7. npm run refresh / npm test / npm run check / npm run build。実行できなければ公開更新しない。
8. 最新SHAを読み直し競合がなければ変更をGitHubへ保存。競合は取得し直して再検証、force上書き禁止。
9. Cloudflare接続済みの場合のみデプロイ完了と本番/data/campaigns.jsonの対象ID・確認日時を検証。GitHub保存と公開反映は別記録。

## 自動処理
- ブラウザーは30秒毎と表示復帰時にJSTと期限を再計算。予定実行が遅れても期限切れは通常一覧から除外。
- 日付だけの締切は当日0時から再確認待ち。翌日0時から終了。時刻を創作しない。
- 公式確認から48時間経過で再確認待ち。情報取得・再確認の成功保証なし。
- npm run refreshは終了済みを配列から削除せず履歴に保つ。独自スクレーパーは稼働しない。
- GitHub Actionsはpush/PR時に検証・ビルド。追加cronは作らない。

## 定期実行（既存枠へ統合）
日本時間8時は新着/当日締切/変更、15時は当日締切再確認/新着、19時は翌日締切/公開検証。既存の担当H/V/Jと15時本選び・順次改修を変更しない。本サイト専任の範囲だけで書込み、他サイトの権限を借用しない。毎週月曜19時に到達可能性と取得成功/失敗/未取得を集計、月初19時に利用/広告のデータ有無を評価。計測未接続なら未測定と記録し、0収益・0訪問へ置き換えない。SNS投稿は別途指示がなければ実行しない。

## 2026-11-04 全体改修後の品質維持

- 広告の現在値は `data/site.json` の `status: approved`、`enabled: false`、`siteSpecificCode: null`。承認済みでも実配信はしていない。旧本文の「申請予定」は過去の手順であり、再申請や配信有効化をこの改修に含めない。
- `npm test && npm run check && npm run build` を公開の必須ゲートにする。buildは内部リンク、canonical・既存GSC、全案件sitemap、出力JSONのバイト一致、広告無効、CSPを検証する。CIの後半がskippedなら公開成功と判断しない。
- 案件総数や終了件数は固定しない。追加・期限経過で変動するため、可変件数のfixtureと各案件ID・履歴・確認日時・引換情報の保持をテストする。件数をテストに合わせて減らさない。
- 正本の新規案件を追加したら、全件検証と新規detail/sitemapを確認。公式情報を確認していないときは `lastVerifiedAt` を更新しない。レイアウト変更と事実再確認は別作業として記録。
- 7日カレンダーは「記録上の応募締切」。再確認待ちを含み、終了・開始前を除く。購入・引換期限のカレンダーと誤記しない。日付未公表の案件は件数に加えない。ジャンル件数・購入不要の件数は確認済みのみ。
- モバイル・デスクトップで上部だけでなく下部ジャンル、期限ガイド、実historyの更新記録、FAQ、footerを確認。カードタイトル・特典文を長くしたfixtureや期限切れの状態でも、情報を省略して見栄えだけを保たない。
- 保存はブラウザー内のID記録。通知、応募済み管理、端末同期の保証は追加していない。プライバシーの削除機能と、保存が無効なブラウザーでの表示も維持。
- 参照先と差別化の根拠は `docs/DESIGN_REFERENCES.md`。参照先の観測は2026-11-04時点であり、各社の実績や優劣を推測で追加しない。
